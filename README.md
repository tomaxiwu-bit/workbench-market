## 这是什么

豆包工作里的「工作台」，是一套预置好的技能、插件和做事偏好。每个人客户端里各有一套，互相看不见——这个站把愿意公开的那份摊开来放着。

现在收着 23 个：15 个别人交出来的（其中 5 条复制链接就能直接导入），加 8 个官方预置场景做索引。

![卡片](docs/preview-cards.png)

## 三类条目，三种拿法

| 类型 | 有什么 | 怎么用 |
|---|---|---|
| **用户分享** | 一条真实的分享链接 | 复制后进豆包工作「导入」，技能和插件一起搬过来 |
| **配方 · 可自建** | 原来卡在哪、一句原话、开场指令 | 照清单把技能勾上，开场指令贴进新工作台的偏好设置 |
| **官方预置** | 豆包工作自带场景 | 左边「工作台」入口直接切换，不用导入 |

每条详情页都写清了：适合谁、它解决什么、原来卡在哪、一句原话、开场指令。**先看「原来卡在哪」那一栏**——那是最能判断这东西你用不用得上的地方。

## 三步用起来

1. **进市集**：打开豆包工作电脑版，左上角「豆包工作」下拉展开，底部「更多工作台」就是市场页；或者直接在浏览器打开上面的线上地址搜。
2. **复制链接导入**：市场页右上角点「导入」，把卡片里复制的分享链接粘进去。
3. **改成自己的**：进「我的工作台」点「使用」，偏好指令可以直接改。调顺手了，回头也交一份出来。

## 投一个自己的

填这张表就行，**不用注册账号，匿名也能提交**：

收到后 1–2 天内整理上架，上架前会先跟你确认署名方式。填之前准备好这四样：

- **分享链接** —— 工作台卡片右上角「分享」复制的那条 `doubao.com` 链接
- **它替你干了什么** —— 一句实话，别写功能清单
- **原来卡在哪** —— 手动做这件事最烦的那一步，别人靠这句判断要不要用
- **一句原话** —— 你跟它说过、或它回过你的一句（选填，但卡片上最显眼的就是它）

不想填表？投稿页底下有一份可复制的模板，填好发我也一样。

## 本地跑（可选）

`docs/` 是纯静态的线上版，不需要服务器。仓库里还留了一份带后台审核的本地全功能版，自己看数据、批量审核用：

```powershell
node server.js
# → http://localhost:8686   后台在 /#/admin，口令在 config.json
```

```
├─ data/store.json    本地版数据（含审核状态、取用计数，不进仓库）

└─ sync-docs.js       本地底库 → docs/items.json 的导出管道
```

## 几条边界

- 工作台的配置只存在你自己的客户端里，本站**只保存公开的分享链接**，不碰任何人的账号数据；也因此无法验证链接是否还有效，靠人工与举报维护。
- 导入别人的工作台前，先扫一眼它预置了哪些技能和插件——工作台能携带偏好指令，相当于别人的一套做事方法，别对来源不明的工作台放敏感权限。
- 无账号体系，没有「我的投稿」列表；投稿走表单，上架靠人工。
- 收录不代表推荐。链接失效、内容不当、侵权，核实后直接下架。

## 给站主：一条投稿怎么上架

<details>
<summary>展开看操作步骤</summary>

1. 打开底表看新记录（<https://my.feishu.cn/base/M10MbFXYbanhCmsKJDdcyZt0njd>），确认链接能导入、简介说清用途、授权那栏选的是「同意」。
2. 在 `tools/build_items.py` 里加一条：有分享链接的写 `kind:"share"`，只有方法论没有链接的写 `kind:"recipe"`（配方要带 `starter` 开场指令）。跑 `python tools/build_items.py`。
3. `node sync-docs.js` → `git add docs && git commit -m "new item" && git push`。

Pages 约 1 分钟后重建。条目分三类：`share`、`recipe`、官方预置（`source: "official"`）。
