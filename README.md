# 工作台市集

一个可公开部署的「豆包工作工作台」收录站：浏览、搜索、复制导入链接，并允许他人投稿，站方审核后上线。

## 两个版本（同一份代码）

| 版本 | 地址 | 投稿方式 | 适合 |
|---|---|---|---|
| **静态版（已上线）** | https://tomaxiwu-bit.github.io/workbench-market/ | 飞书公开表单，匿名可填，站主整理后上架 | 公开给人看，零服务器成本 |
| **本地全功能版** | `node server.js` → localhost:8686 | 网页表单直接写入，后台口令审核 | 想零门槛收投稿、自己做审核 |

静态版在 `docs/`，Pages 从 main 分支的 `/docs` 发布；仓库：https://github.com/tomaxiwu-bit/workbench-market

### 一次投稿怎么上架

投稿走飞书公开表单（不用注册账号、匿名可填、不用登录）：

<https://my.feishu.cn/share/base/shrcnUcOhmmrxYTQnGYhgTK4UOd>

收到后三步：

1. 打开底表看新记录（<https://my.feishu.cn/base/M10MbFXYbanhCmsKJDdcyZt0njd> ），确认链接能导入、简介说清楚用途、授权那栏是「同意」
2. 在 `tools/build_items.py` 里加一条：有分享链接的写 `kind:"share"`，只有方法论没链接的写 `kind:"recipe"`（配方会带「开场指令」，别人照着自己搭）；然后跑 `python tools/build_items.py`
3. `node sync-docs.js` → `git add docs && git commit -m "new item" && git push`

Pages 约 1 分钟后重建。条目分三类：`share`（有链接、点一下就能导入）、`recipe`（配方，给开场指令自建）、官方预置。

> 表单那条链路只负责「收」，上架仍然要人过一遍——链接失效、夹带广告、冒名的最好在进站前就拦掉。

## 它有什么

- **市集首页**：按场景分类（金融投研 / 医疗健康 / 教育教学 / 创意设计 / 求职发展 / 数据分析…）、搜索、最新 / 最热排序
- **条目详情**：预置技能与插件、适合人群、使用说明、导入链接一键复制、推荐文案复制
- **投稿页**：一键打开飞书公开表单（匿名、免登录、1–2 天上架），另附一段可复制的投稿模板，不想填表发微信也行
- **审核后台**：口令进入，逐条通过、拒绝、删除
- **防滥用**：同一 IP 每小时最多 5 次投稿、10 次举报；只接受 doubao.com / doubao.link / feishu.cn 域名的链接；所有输入做长度与字符清洗
- **数据**：零依赖，落在 `data/store.json`，写入用临时文件 + 重命名，避免写坏

## 启动

```powershell
node server.js
```

打开 http://localhost:8686 。也可以双击 `启动.cmd`（会弹一个命令行窗口，关掉即停止）。

管理口令在 `config.json` 的 `adminToken` 字段，后台地址 `/#/admin`。换口令：改 `config.json` 后重启。

## 目录

```
workbench-market/
├─ server.js            后端（零依赖 Node，仅用内置模块）
├─ config.json          管理口令（勿提交到公开仓库）
├─ data/store.json      数据（首次启动自动生成并写入 8 条官方预置索引）
└─ public/index.html    前端（单文件，原生 JS + hash 路由）
```

## 公开上线：三条路

### A. 先给别人看一眼（已配好）

`tools/cloudflared.exe` 已经下载到位，双击 **`开启公网.cmd`** 即可把本机服务映射到公网。

- 本地站：`http://localhost:8686`（先双击 `启动.cmd` 让服务跑着）
- 公网地址：**https://assumptions-europe-listen-chancellor.trycloudflare.com**（2026-11-19 首次开通）
- 这个窗口**不能关**，关了地址就失效；电脑关机 / 重启后地址会变，重新跑一次 `开启公网.cmd` 拿新地址

验证过的：公网首页 200、投稿写入正常、审核链路正常。

缺点是地址每次重启都变、内地访问速度看线路，适合内测，不适合当正式站。

### B. 正式站（内地访问，需要域名 + 备案）

1. 买一台轻量云服务器（2 核 2G 足够，阿里云 / 腾讯云）
2. 装 Node 20+，把整个目录传上去，`node server.js` 起服务（建议用 pm2 或 systemd 守护）
3. 用 Nginx 反代到 8686，绑域名，开 HTTPS
4. **域名解析到内地服务器前必须完成 ICP 备案**；涉及用户投稿（UGC），按平台要求还需配置内容审核与举报入口——本站在后台审核 + 详情页举报已做了基础版

### C. 正式站（海外服务器，免备案）

同上，但服务器放香港 / 新加坡，域名不用备案，内地访问延迟略高。适合先跑起来验证有没有人用。

## 运营建议

- 上线初期**全部人工审核**：链接能不能导入、简介是否说清用途、有没有夹带广告
- 每 2 周清一次失效链接（详情页有举报入口，`data/store.json` 里 `reports` 字段可查）
- 备份就是复制 `data/store.json`，建议每天定时拷一份
- 想加「按导入量排序」的榜单，`copies` 字段已经在累计，改前端 `sort=hot` 的展示即可

## 已知边界

- 工作台配置只存在于用户客户端，本站只保存**分享链接**，无法验证链接是否仍然有效，只能靠人工与举报
- 没有账号体系，无法做「我的投稿」；需要的话下一步加登录
- 单机 JSON 存储，日投稿量上百后再换 SQLite / Postgres
